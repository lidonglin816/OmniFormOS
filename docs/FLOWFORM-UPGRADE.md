# FlowForm 专业版升级说明

入口：`http://127.0.0.1:3000/#flowform`

## 当前结构

FlowForm 已拆分为七个真实工作区：流程工作台、AI 流程设计、可视化编辑器、审批中心、流程测试、运行监控和发布管理。工作台统计、流程卡片、审批动态与六套模板全部读取实际状态。

可视化编辑器复用 React Flow，提供节点库、缩放和平移、MiniMap、自动布局、撤销重做、分支端口、连线点击删除、可折叠属性区、全屏模式和调试控制台。条件节点的“满足/不满足”使用独立颜色与正交连线；运行回放会高亮实际节点与连线。

## 服务端业务闭环

- 流程定义、版本快照、实例、通知和审计日志保存在 `data/flowform.sqlite`。
- 首次打开会迁移原 `omniformos.v1.flowform` 浏览器数据，并保留原始迁移备份。
- 发布前由服务端检查唯一入口和出口、孤立节点、条件双分支、循环、不可达节点与审批人。
- 正式申请只能运行已发布且未修改的版本；实例保存不可变流程快照。
- 服务端支持同意、驳回、退回、撤回、转交和加签，并记录处理人、意见、时间与通知。
- 条件引擎支持数值、文本、日期、枚举以及 AND/OR 组合；不执行用户代码。
- 测试中心调用同一套服务端条件与节点执行逻辑，模拟记录与正式实例分开标记。
- 发布中心保存不可变版本快照，可停用、复制、归档，并将历史版本恢复为新草稿。

## AI 流程设计

AI 仅通过服务器调用 OpenAI-compatible `chat/completions`，密钥不会进入浏览器。模型必须返回结构化流程 Schema；服务端完成引用、节点、分支、角色与有向无环图校验后才显示差异预览，用户确认后才能应用。

在 `.env` 中配置：

```text
OMNIFORM_AI_BASE_URL=https://your-provider.example/v1
OMNIFORM_AI_API_KEY=...
OMNIFORM_AI_MODEL=...
```

未配置时接口明确返回不可用，不生成固定答案；模板和手动流程仍可使用。

## 平台联动

运行数据保留 `projectId`、`applicationId` 与来源业务标识。ExamCraft 已通过原试卷和答卷 ID 生成培训确认流程；现有工作区对象仍同步服务端最新数据，FormPilot、AdaptForm、DocMorph、TableMind、LabForm 与 AppCanvas 可继续复用统一 ID 接入。

本地项目当前为单工作区应用，没有完整组织账号系统。关键状态流转已经迁到服务端，但生产部署前仍需接入统一登录、角色目录和组织级权限策略。

## 验证

执行 `npm run check`、`npm test`、`npm run build`。自动测试覆盖发布、持久化、大额分支、审批闭环、文本/枚举/日期规则、转交、加签、退回，以及未配置 AI 时拒绝伪造结果。浏览器验收覆盖工作台、三栏画布、1500 元模拟路径和 1024px 平板布局。
