# 备份与恢复

顶部“导出工作空间备份”现在下载 `.ofbackup`：包含八大模块的 SQLite 完整快照（含 WAL 中已提交记录）、数据库内附件、发布历史、账号配置，以及当前站点浏览器 localStorage。密钥环境变量不进入备份。文件包含真实业务数据，应按业务备份保管。

## 恢复到新目录

```powershell
node scripts/restore-workspace.mjs "D:\备份\OmniFormOS-2026-10-21.ofbackup" "D:\OmniFormOS恢复\2026-10-21"
node scripts/start-restored-workspace.mjs "D:\OmniFormOS恢复\2026-10-21" 3400
```

随后打开 http://127.0.0.1:3400/ 。恢复工具会校验每个文件 SHA-256、八个模块完整性与 SQLite integrity_check；拒绝覆写已有目录。原服务和原数据库不变。切回原服务即可回退。

恢复目录内 `browser-storage.json` 是浏览器工作区的原始键值备份，SQLite 模块无需它即可读取数据库。旧版浏览器应用与未发布 DocMorph 原稿需要此浏览器数据。在新恢复端口打开 `/restore-browser.html`，选择该文件并点击导入，随后打开工作区。

当前服务依旧是本机个人工作区。此变更没有把管理接口暴露到其他设备，也没有添加外部部署、真实组织身份或 AI 服务凭据。跨设备部署应单独配置身份与访问边界。

## 已验证

- 带 WAL 未检查点数据的八个数据库备份与恢复。
- 备份篡改被拒绝、已有目录不被覆盖。
- HTTP 备份真实下载后恢复全部数据库。
- 无工作区会话不能导出；正常本机工作区自动建立 HttpOnly 会话。

建议在无业务写入的窗口执行备份。单个 SQLite 快照具备一致性；多个数据库不承诺对来自其他进程的并发写入形成全局事务。
