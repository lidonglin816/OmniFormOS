# FlowForm v0.4 · 历史原型说明

> 当前实现已升级为服务端持久化的 FlowForm 专业版。本文件保留旧版行为说明，最新架构、配置和验证结果见 [FLOWFORM-UPGRADE.md](./FLOWFORM-UPGRADE.md)。

入口：`http://127.0.0.1:3000/#flowform`，也可从侧栏进入。

## 已实现流程

1. **规则生成**：输入报销或请假需求，生成新流程草稿。识别「超过 / 大于 / 高于 + 数字」阈值。默认报销流程为申请 → 主管审批 → 金额判断 → 大额财务审批 / 小额直接通知 → 结束。请假模板使用天数字段和总经理审批。
2. **React Flow 画布**：节点拖动、缩放、适应视图、小地图、自定义节点与分支端口。右侧可以编辑名称、审批人、字段、比较规则和通知内容，也可以用连接表单替代拖动连线。
3. **结构编辑与校验**：添加审批、条件、通知节点；添加演示审批人；替换或移除连线。禁止自连、连入发起节点、从结束节点连出及产生循环。发布前校验唯一入口/出口、全部节点可达、条件双分支和审批人配置。
4. **本地发布**：编辑配置后版本递增，必须重新发布才可发起申请。拖动布局只更新展示位置，不改变业务版本。
5. **申请与审批**：填写标题、金额、天数和说明，申请进入当前审批人的待办。切换演示操作人后可同意或驳回；串行节点形成多级审批。
6. **驳回与撤回**：驳回必须填写原因；申请人可以撤回仍在审批中的申请。已通过、已驳回和已撤回申请不能再处理。
7. **执行时间轴**：展示节点进入、审批意见、条件比较值、实际分支、结束结果和站内通知。
8. **流程测试**：对草稿或发布版本模拟执行，自动同意经过的审批节点，保存带「模拟」标记的完整记录；不混入真实本地申请统计。
9. **通知与审计**：自动生成当前审批人待办通知及申请人结果通知，可标记已读。保存流程配置修改和执行日志，可导出流程、全部实例和审计 JSON。

## 数据与执行规则

- 数据保存在原有 `omniformos.v1` 的 `flowform` 属性内：`definitions`、`runs`、`audit`。模块页签、操作人及当前流程/实例使用 sessionStorage。
- 申请启动时复制完整流程定义。在途申请不会因后续改版变更审批人或分支。
- 条件字段为金额 `amount` 和天数 `days`，均要求非负有限数值。操作符支持 `>`、`>=`、`<`、`<=`、`=`，按 JavaScript 数值比较，不使用代码求值。
- 当前支持单人节点、串行多级审批和条件分支汇合，不包含并行会签、或签、循环和定时任务。
- 默认申请人固定为演示「申请人」。操作人切换用于功能体验，前端状态检查不构成真正的身份认证或权限隔离。
- 站内通知只写入浏览器，不发送邮件、短信、企业消息或 Webhook。
- 审计日志为本地普通数据，尚无服务端持久化、签名、防篡改和合规审计保证。
- 本地规则生成不调用大语言模型，不理解任意自然语言。没有自动绑定 FormPilot 表单提交、正式数据库或外部系统。

## 构建与维护

现有页面仍使用原生 ES 模块；React Flow 画布单独由 React 组件挂载，并在切换视图前卸载。

```powershell
npm install
npm run build
npm run check
npm test
npm run dev
```

`src/flow-canvas.jsx` 为画布源文件；`scripts/build-flow.mjs` 使用 esbuild 生成 `public/vendor/flow-canvas.js` 和同名 CSS。生成资产随项目保留，正常本地启动可直接使用；修改画布源代码后需重新构建。第三方代码保留许可证注释。

参考：[React Flow 交互文档](https://reactflow.dev/learn/concepts/adding-interactivity)、[自定义节点与端口](https://reactflow.dev/learn/customization/handles)。
