## 1. 项目概述（1-2 页）
- 定位：AI 原生全场景低代码应用生成与智能业务自动化平台（8 合 1）
- 八大引擎一句话分工表：FormPilot（应用生成）/ ExamCraft（测评）/ FlowForm（审批）/ DocMorph（文档数字化）/ AdaptForm（智能表单）/ TableMind（数据分析）/ LabForm（科研实验）/ AppCanvas（可视化搭建）
- 目标用户与核心场景（校园/中小企业业务自动化）

## 2. 意图控制策略（4-5 页）★重点
### 2.1 意图输入分层
- 自然语言描述 → 本地领域模板 + 规则引擎解析（FormPilot 蓝图生成）
- 明确指令式迭代（"添加字段：预算，类型：数字，必填"）→ 增量 Schema 变更，保留已有数据与字段 ID
- 大模型增强通道：ExamCraft AI 出题、AI 创作中心（OpenAI 兼容接口，可配置可降级）

### 2.2 Prompt 上下文设计
- 系统上下文注入：模块角色 + 输出 JSON Schema 约束 + 示例（few-shot）
- 出题链路：大纲解析 → 题型分发 → 结构校验 → 人工复核入库；超时/失败明确降级为本地模板生成
- 意图歧义处理：预置示例芯片（客户/报销/库存/项目）收敛输入空间

### 2.3 输出约束与防御
- 结构化输出必须通过模型层校验（字段类型、必填、枚举）才进入渲染
- AI 配置三要素（base_url/model/api_key）运行时可切换，密钥仅存本机（.env / ai-config.json），前端打码
- 失败可观测：连接状态卡、请求错误日志、诊断 JSON 导出

## 3. 总体架构设计（4-6 页）★重点
### 3.1 分层架构图
- 展示层：原生 JS/CSS SPA（hash 路由）+ Electron 桌面壳（双部署同构）
- 服务层：Node.js `server.mjs`（3100/3102 双端口），按模块拆分 `src/*-service.mjs`
- 数据层：网页端 localStorage/sessionStorage 原型数据；桌面端 8 个 SQLite 工作区数据库
- AI 层：`ai-config.mjs` 统一配置路由 → OpenAI 兼容上游

### 3.2 AI 生成代码的架构约束（如何约束它）
- 模块边界：每个引擎独立 model/js/css 命名空间，跨模块只经工作台事件通信
- 渲染安全：用户输入统一 `esc()` 转义；动态内容经白名单过滤
- 主题体系：CSS 变量分层（`--desk-*` / `--module-*`），深色主题经专用层级覆盖，禁止全局 `!important` 污染（记录红绿灯/侧边栏两个真实案例的修复）
- i18n 约束：所有界面文案经翻译引擎（EXACT 词典 + PHR 词组 + MutationObserver），业务数据与界面文案分离
- 质量门禁：`npm run check`（130+ 文件语法检查）+ `npm test`（35+ 测试文件）+ 模块级验收文档

### 3.3 关键机制
- 认证：本地加盐 SHA-256；可选 Supabase 邮箱认证（`auth-model.js` 回调地址白名单校验）
- 工作流：FlowForm 实例使用独立流程快照，改版不影响在途申请
- 备份恢复：工作区 JSON 导出 + 桌面端 SQLite 备份（`workspace-backup.mjs`）
