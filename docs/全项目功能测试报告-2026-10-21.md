# OmniForm OS 全项目首轮功能测试报告

测试日期：2026-10-21。范围：当前本地版本，浏览器实例 http://127.0.0.1:3100 。本次审计未修复产品代码；新增审计脚本和证据文件，构建命令重新生成前端资源。缺陷复现使用内存 SQLite，不向现有业务库写测试记录。浏览器巡检会正常触发模块初始化及读取。

## 结论

项目已有可运行的八模块基础与多条业务闭环，但尚不能认定“功能完善、可用于正式多人业务”。现有自动化用例全部通过，补充测试仍复现了发布中断、数据覆盖、校验绕过及重复 ID 等缺陷。应先修复数据完整性和发布版本问题，再补充真实 AI、外部访问与完整备份验收。

## 验证结果与边界

- npm test：147 项通过，0 失败、0 跳过。结果 artifacts/project-audit-tests.txt。
- npm run check：通过。结果 artifacts/project-audit-check.txt。
- npm run build：通过，包含 FlowForm、DocMorph、ExamCraft、TableMind、首页资源。结果 artifacts/project-audit-build.txt。
- 浏览器：FormPilot 6、ExamCraft 7、FlowForm 9、DocMorph 6、AdaptForm 6、TableMind 7、LabForm 8 个主导航，以及 AppCanvas 编辑器 4 面板，共 53 个切换通过选中状态检查，无阻塞性 alert。证据 artifacts/project-audit-browser.json。
- AppCanvas 当前浏览器会话错误日志为空；未对全部模块收集完整网络日志，不能据此认定全项目无控制台错误。
- 补充后端复现：8 条记录，全部使用 :memory: 数据库。证据 project-audit-reproductions.json、project-audit-extra.json。
- 本轮没有完整实测每一种文件格式、断网重启恢复、大数据量、真实外部 AI、移动真机、多用户部署。导航可打开不等于页面内所有业务操作通过。

## 已确认缺陷

| 编号 | 优先级 | 模块 | 问题及复现证据 | 应改进的行为 |
|---|---|---|---|---|
| A01 | P1 | AdaptForm | 先发布表单，公开访问 200；编辑保存草稿后，同一链接变成 404。保存接口直接将同一对象 status 改为 draft，公开接口又只读取此对象。 | 草稿与发布快照分离；保存草稿不停止线上版本，只有明确停用才下线。 |
| A02 | P1 | AdaptForm | 从同一版本取得 A/B 两份表单，A 修改名称保存，B 修改说明后保存，B 返回 200 并覆盖 A 名称。 | 按表单 revision 做乐观锁，旧版本保存返回 409，提供差异及恢复入口。 |
| A03 | P1 | AdaptForm | 发布 v1 → 保存草稿 → 再发布，版本列表得到 [1,1]。 | 从全部历史版本取最大值 +1；版本快照唯一，不依赖草稿 status。 |
| A04 | P1 | LabForm | 同一实验开 A/B 两份，A 改名称，B 用旧对象改目的并保存，返回 200，名称恢复旧值。 | 项目级 revision 校验，数据行修改采用稳定 ID 与并发合并策略。 |
| A06 | P1 | TableMind | 单条 PATCH 将必填姓名清空、数字年龄设为“不是数字”，返回 422；相同内容 bulk/update 返回 200 并已入库。 | 批量与单条共用必填、类型、唯一性、关联校验；全批次校验通过才提交。 |
| A07 | P1 | TableMind | 连续 POST 两条 id=same_id 的记录，均返回 200；库中存在两条相同 ID。 | 新增拒绝重复 ID 或完全由后端生成；防止更新、删除和关联选错对象。 |
| A08 | P2 | TableMind | CSV 中带引号的值“  保留空格  ”解析后变成“保留空格”。parseDelimited 对全部单元格执行 trim。 | 保留引号字段原值；清洗空格改成可选择、有预览的步骤。 |
| B01 | P1 | 全局备份 | 顶部“导出工作空间备份”仅 download({...state})，没有读取各模块 SQLite；已服务端化的考试在浏览器状态中只保留标记。此 JSON 不能恢复整个项目。源码确认：public/app.js:52、293。 | 提供服务器统一备份/恢复，涵盖所有数据库、附件、Schema 和发布版本；实施一次恢复演练。未完成前应改名为“浏览器工作区导出”。 |

P1：正式业务使用前修复；P2：下一轮质量完善。没有把未验证的部署风险标成当前已发生的数据泄露，也未发现可据本轮证据确认的 P0 故障。

## 已确认的功能与架构限制

| 编号 | 优先级 | 范围 | 现状与影响 | 建议 |
|---|---|---|---|---|
| C01 / A05 | 多人部署前 P1 | 权限边界 | 内存复现：AppCanvas 私有应用的 /api/canvas/preview/{id} 无工作区会话仍返回 200，角色 admin。当前程序绑定 127.0.0.1、采用本机免登录设计，因此这属于本机信任模型限制，不是已证明的远程攻击。全局团队页也明确是角色演示。 | 若用于多人或代理发布，设计接口、预览接口和配置接口必须有统一工作区身份与权限；保持免登录时明确仅供本机个人使用。 |
| C02 | 对外考试/申请前 P1 | 发布可达性 | server.mjs 只监听 127.0.0.1。当前复制的本机链接不具备跨设备访问能力。 | 独立设计部署地址和访问权限，用考生/申请人的另一台设备验证。不要仅将监听改成公网后宣称完成。 |
| C03 | P2 | AI 功能 | 当前 FormPilot、AppCanvas 等页面显示模型待配置；源码在缺少 OMNIFORM_AI_BASE_URL/API_KEY/MODEL 时明确返回 503。模板及规则分析可运行，但本轮无法验收真实 AI 端到端质量。 | 配置后逐模块验证结构化输出、错误恢复、超时、取消、真实统计依据、成本及请求日志；不要把模板结果算作 AI 验收。 |
| C04 | P2 | 外部连接器 | public/app.js:287 的连接器入口直接展示“此连接器尚未实现”。 | 将规划项与可用功能区分，补服务端授权、实际调用、重试和运行记录。 |
| C05 | P2 | ExamCraft 个人画像 | public/exam-student.js 的个人报告明确只包含当前考试授权答卷；历史考试需要分别打开原链接。 | 若要满足跨考试个人趋势，先建立可验证的考生身份绑定和授权，再聚合历史，不能凭同名匹配。 |
| C06 | P2 | 持久化与状态提示 | 顶栏除考试外使用固定“本地已保存”文案，并非各模块请求/草稿状态的统一结果。 | 区分编辑中、保存中、已保存、保存失败、离线与冲突，标注最后成功保存时间。 |

## 各模块优缺点

| 模块 | 本轮确认的优点 | 主要不足或待验收 |
|---|---|---|
| FormPilot | 六个工作空间入口可用；已有规划/构建/角色/发布隔离的自动化闭环。 | AI 未配置；跨模块构建有步骤记录，但仍需做中途失败与重试后的残留资源专项测试。 |
| ExamCraft | 七个入口可用；统计、权限和真实评分有自动化覆盖。 | 考生侧跨考试画像尚缺统一身份；外部学生访问与断网考试恢复需专项实测。 |
| FlowForm | 九个入口可用；校园申请、审批、资源冲突、幂等、事件联动有自动化覆盖。 | 本轮未重新逐项实测所有校园模板和定时节点，邮件/外部通知不能以站内通知测试代替。 |
| DocMorph | 六个入口可用；本地解析资源构建成功，有来源审核及发布提交测试。 | 尚未进行扫描件质量、复杂表格、多页 PDF、超大文档和 OCR 失败恢复专项。 |
| AdaptForm | 六个入口可用；动态字段和规则有基础测试。 | A01/A02/A03 影响正式发布与多人编辑，是重点整改模块。 |
| TableMind | 七个入口可用；单条字段校验能够拒绝非法值。 | A06/A07 会破坏数据完整性；A08 会静默改变导入文本。 |
| LabForm | 八个入口可用；拟合、单位、不确定度等数学测试通过。 | A04 旧窗口覆盖；真实仪器文件和大样本计算性能待验收。 |
| AppCanvas | 四个编辑面板可用，测试覆盖页面、组件和发布行为。 | 预览仍信任本机工作区；多人部署身份边界未完成。 |

## 改进顺序

1. 先修 TableMind 校验/重复 ID，AdaptForm 发布快照/版本号/冲突，LabForm 冲突；给每项增加能先失败再通过的回归用例。
2. 完成真正覆盖 SQLite 和附件的统一备份及恢复演练。
3. 明确本机个人工具或多人校园系统的产品边界；多人方案先完成身份权限和部署，再验收公开链接。
4. 配置真实 AI 后分别验收八模块；完善错误信息、重试、取消及保存状态。
5. 做断网/重启/多窗口、移动真机、复杂文件、至少 1 万条数据、长时间运行与导出一致性专项；以指标记录性能，不提前给出无依据的性能评级。
