# DocMorph v0.5 · 智能文档数字化引擎

入口：`http://127.0.0.1:3000/#docmorph`。沿用平台统一的浅色、紫色界面。

## 支持格式

| 文件 | 实际处理 | 来源与预览 |
| --- | --- | --- |
| PDF | PDF.js 提取文本；无文字页可逐页 OCR | PDF 原版式 / 提取文本切换，页码及行号 |
| Word DOCX | Mammoth 提取段落文本 | 提取原文及行号；不还原 Word 分页和版式 |
| Excel XLSX | ExcelJS 读取工作表及单元格 | 工作表名、单元格地址；公式只读缓存值，不执行公式 |
| PNG / JPG / WEBP | Tesseract.js 简体中文及英文 OCR | 扫描原图 / OCR 原文切换，页及行定位 |
| UTF-8 TXT / 粘贴原文 | 逐行解析 | 行号与原文 |

暂不支持旧版 DOC / XLS、手写专用模型或任意复杂表格理解。旧文件需另存为 DOCX / XLSX。文件最多 15 MB；PDF 最多 30 页；Excel 最多 12 个工作表，每表最多 2000 行、100 列；提取文本最多 10 万字。

## 使用流程

1. 导入文件，或使用示例与「粘贴原文」。解析完成后建立独立文档和候选字段，不覆盖其他文档。
2. 左侧查看原文，右侧查看数字表单。点击右侧字段的来源按钮，左侧滚动并高亮对应原文。PDF 页码和 Excel 单元格地址保留在字段来源中。
3. 图片导入后点击 OCR。扫描 PDF 先选页，再运行当前页 OCR。文字识别由本地模型执行；识别结果和原件都不上传外部服务。
4. 点击字段编辑按钮，校正名称、类型、必填、选项、数值范围、长度、填写说明及来源位置。支持手动添加或移除候选字段。
5. 使用「修正原文」处理漏识别、乱码或手工录入。此操作重建全部候选字段并清除复核标记，界面在保存前明确说明。重新 OCR 会重建当前页字段；其他页保留。
6. 逐项勾选已复核，或人工检查后批量标记。只有全部字段通过定义校验并复核后，才启用「送入表单设计器」。
7. 送入设计器会创建独立应用，复制字段、选项、限制、填写说明和来源快照。之后可以真实填写并提交业务记录，字段约束继续生效。
8. 同一文档同一修订再次送入时打开已生成应用；修改文档后重新生成新应用，保留此前应用及业务数据。

## 规则识别范围

支持类似以下规范文本，及常见独立标签（姓名、邮箱、电话、部门、日期等）：

```text
姓名（必填，最多20字）：________
电子邮箱（必填）：________
联系电话（11位）：________
部门（单选）：研发部 / 市场部 / 财务部
月度预算（数字，0~50000）：________
备注（最多200字）：________
确认信息真实（必填，勾选）：本人已核对。
```

生成字段类型包括文本、多行文本、邮箱、电话、数字、日期、单选、多选及确认勾选。中文 OCR 中的字间空格在字段推断时归一化；原始识别文本仍完整保留为证据。说明、提示、要求可以附着到前一字段。

这是本地启发式识别，未接入大语言模型，也不保证复杂版式、表格语义或手写内容的准确率。OCR 置信度来自实际字符识别，不代表字段、选项或规则准确率。没有识别到字段时显示空结果，不伪造候选项，用户可手工补录。

## 数据与构建

- 文档定义、提取文本、字段、复核标记和修订历史保存在 `omniformos.v1.docmorph`。
- 原文件使用 IndexedDB 数据库 `omniformos-docmorph-files` 保存，刷新后可重新查看原件。清除浏览器站点数据会删除原件和定义。
- Schema 导出包含字段与原文来源。平台 JSON 备份包含文档定义，但**不包含 IndexedDB 原件**；应另行保留原文件。当前没有完整工作空间备份导入功能。
- 本地 OCR 所需 worker、WASM、中英文语言包及 PDF 字体资源随构建复制到 `public/vendor/docmorph/`，运行时从当前本机服务读取，不依赖 CDN。
- 解析器按需加载，不影响其他模块的首次加载。修改 `src/doc-parser.js` 后执行 `npm run build`；首次安装依赖需要网络。
- 源码文件：`public/docmorph-model.js`、`public/docmorph.js`、`public/docmorph-files.js`、`public/field-rules.js`、`src/doc-parser.js`。
- 解析与 OCR 均在前端，尚无多人同步、账号隔离、云端存储或生产发布能力。依赖树的 npm 审计当前仍有 5 项 moderate 通告，涉及解析库的传递依赖；正式发布前需处理及复核。

参考：[PDF.js](https://mozilla.github.io/pdf.js/)、[Mammoth](https://github.com/mwilliamson/mammoth.js)、[ExcelJS](https://github.com/exceljs/exceljs)、[Tesseract.js API](https://github.com/naptha/tesseract.js/blob/master/docs/api.md)。
