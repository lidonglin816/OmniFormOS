# ExamCraft 专业测评工作区

## 现状盘点与实施范围

保留：原题目与来源 ID、试卷题目快照、历史答卷和人工评分、导入校验、拖拽排序、原 OmniForm OS 侧栏与导航。

改造：三栏题库编辑器、试卷工坊、成绩分析、模块嵌入；六种题型、分类/标签/审核、版本恢复、预览折叠与全屏。

新增：独立工作首页、四种 AI 出题入口、审核队列、规则组卷、考生独立页面、服务端计时与自动收卷、教师登录、SQLite 数据库、ECharts 六种统计图、真实 AI 辅助阅卷和分析接口。

## 运行与首次迁移

要求 Node.js 24 及以上，使用内置 SQLite。执行 `npm install`、`npm run build`、`npm start`，访问 `http://127.0.0.1:3000/#exam`。

首次打开由用户设置至少八位教师密码；密码采用 scrypt 加盐散列存储，教师会话为 HttpOnly、SameSite=Strict Cookie。考生持专属邀请链接和对应编号、姓名进入，不访问教师管理接口。

数据库位于 `data/examcraft.sqlite`，包含 schema 迁移记录和原始迁移备份表。首次成功设置教师密码时，导入该浏览器原 `omniformos.v1.examcraft` 的全部来源、题目、试卷、答卷和草稿，保留原 ID。迁移后浏览器工作空间只保存数据库标记，题目答案不会继续镜像到 localStorage；其他七个模块仍按原方式保存。其他已有浏览器的旧数据会按 ID 追加迁移，冲突原件保存在独立迁移备份表，可在资料页下载，避免覆盖现有记录。旧的未交卷答卷会建立续答邀请并重新给予一次原定考试时长，原开始时间另行保存。

备份数据时应同时备份整个 `data` 目录；停止服务后复制，或使用 SQLite 的在线备份机制，避免仅复制有未检查点 WAL 的主文件。顶部工作空间导出在教师登录后包含已加载的测评数据快照，教师密码不在 JSON 导出内。

本地服务仅监听 `127.0.0.1`。当前不是公网部署；跨设备考试需要受控服务器、HTTPS 和对应站点地址，专属邀请属于凭证，应仅提供给对应考生。

## 工作流程

1. 工作首页查看真实数量、最近试卷、考试动态与模板。模板进入可编辑规则组卷配置，不填入伪造试题。
2. AI 中心选择自然语言、文档、题库扩展或知识点模式，填写学科、章节、题型、数量、难度、分值、语言、解析和来源要求。上传复用 DocMorph 的 PDF/DOCX/TXT 解析；也可直接导入 DocMorph 已有文档原文。
3. 生成只通过真实服务端 AI 请求进行。返回结构校验、题型和答案索引校验、重复题干检测、绑定引文原文匹配后，保存为 `pending`，不会自动发布。专业答案与数学推导由教师复核。
4. 题库支持单选、多选、判断、填空、简答、计算。题干与解析渲染安全的粗体/斜体和 KaTeX 数学公式；附件限 1 MB PNG/JPEG/WebP。编辑草稿自动保存，正式保存形成新版本并重新待审；审核通过后才用于新考试。
5. 自动组卷按审核状态、题型数量、去重、知识点覆盖、总分和时长配置生成快照。支持按知识点覆盖百分比分配题数，使用二部图最大流同时满足题型与知识点配额；目标难度比例按题库供给匹配；不足时显示实际分布与偏差提示，不伪造满足条件。可以手动增删、调整分值、拖拽排序。B 卷为同题异序，不宣称不同题等值。
6. 旧试卷或副本可使用“同步题库审核版本”更新草稿题目快照，保留试卷自定义分值；已开考试卷不可修改或删除。发布前校验所有题目审核通过、没有重复且分值有效。
7. 发布设置有效起止时间、考生名单和关联业务应用，每位考生获得随机专属链接。学生端核对编号姓名后开始计时；考生接口不返回正确答案、关键词、解析、教师历史或其他答卷。
8. 答案和标记自动保存到服务端，网络失败时本机缓存并重试。服务端以开始时刻、试卷时长和考试截止时间取较早值作为期限，每秒检查自动收卷；截止后拒绝改答。
9. 客观题服务端确定性评分。填空为标准文本规范化匹配，不执行数学表达式；等价表述或复杂计算应使用计算/简答题。主观题关键词建议不计入最终成绩，真实 AI 辅助意见单独记录模型、依据和时间，人工评分必须填写依据。
10. ECharts 分析来自已完成评分的真实答卷，包括成绩分布、提交成绩趋势、知识点热力图、题目正确率、难度得分和考生知识点雷达。没有数据时显示空状态。AI 学情报告记录生成时样本量，不伪造分析数据。

## AI 配置

复制项目根目录 `.env.example` 为 `.env`，在本机设置：

```
OMNIFORM_AI_BASE_URL=<支持 chat/completions 的服务基础地址，通常包含 /v1>
OMNIFORM_AI_API_KEY=<真实密钥>
OMNIFORM_AI_MODEL=<可用模型名称>
```

重启服务后生效。密钥只在服务器环境中使用，前端只收到模型名称与已配置状态。接口必须支持 JSON 对象输出和 OpenAI 兼容的 `chat/completions` 协议。未配置时三项 AI 功能明确返回“尚未配置”，不会调用原规则模板伪装生成。可先使用已有题库或手动建题完成考试闭环。

## 平台联动

- DocMorph：复用已导入文档与原文位置，不复制文档解析实现。
- FormPilot：为已有业务应用保存同一 paperId 的测评关联；发布可直接选择关联应用。
- TableMind：从已完成评分答卷幂等同步真实成绩，保留原记录，按 attemptId 更新同一条数据。
- FlowForm：把已通过且完成复核的答卷转换为主管确认审批任务，保留 paperId/attemptId；重复同步不重复创建。该模块仍按现有本地流程引擎运行，须主动同步。
- AppCanvas：创建绑定同一 paperId 的测评页面；入口打开教师试卷管理，考生仍使用受控专属邀请，避免把任意身份入口公开给所有访问者。

这些联动保留现有平台业务应用 ID；平台其余七个模块仍是原有浏览器工作空间体系，本次没有把它们改造成统一后端身份平台。

## 验证

`npm run check`、`npm test`、`npm run build`。新增测试覆盖旧数据迁移、审核限制、规则组卷、教师认证、考生授权、答案隐藏、保存/交卷、客观题评分、主观题复核、截止后拒答、服务重启持久化和 AI 未配置错误。

浏览器验证使用独立端口与独立测试数据库，不在用户的正式题库里添加验收考试。
