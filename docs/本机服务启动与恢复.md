# 本机服务启动与恢复

2026-10-24：已将日常启动改为独立后台守护，避免临时终端结束后 3100 服务随之停止。

- 双击根目录 `Start-OmniForm.cmd`：确认服务就绪后打开应用；重复启动复用已运行服务。
- 已在当前用户 Windows 启动文件夹安装 `OmniFormOS.lnk`，登录后自动后台启动，不需管理员权限。取消自动启动时删除该快捷方式即可。
- 后台守护在服务退出后重启，连续失败的等待时间从 1 秒逐步增加到 30 秒。服务端口保持仅监听 `127.0.0.1`。
- 原数据库路径沿用 `scripts/start-workspace.mjs`。守护状态位于 `data/workspace-3100.pid`，日志位于 `artifacts/workspace-3100.log` 和 `artifacts/workspace-3100-supervisor.log`；日志在下次启动时超过 10MB 会截断。
- `/api/health` 提供不含业务信息的健康响应，启动器等待确认后才报告启动成功。端口被其他程序占用时会明确提示查看日志。

实测：主动结束服务子进程，守护保持运行，约 3 秒内新的服务进程健康响应成功；再次运行启动器未创建第二个监听服务。

计算机关机、休眠、用户退出登录期间，本机地址不可访问；重新登录会启动。浏览器已经显示的连接错误页仍须重新加载。守护负责进程退出恢复，不能保证自动修复业务代码错误、磁盘故障或事件循环卡死。
