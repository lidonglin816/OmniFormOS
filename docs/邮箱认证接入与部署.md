# Email authentication — setup and deployment

本次按“先完成接入和配置说明”的要求实现。尚未创建 Supabase 项目，未发送真实邮件，也未完成线上认证验收。页面、服务端集成和自动化契约测试已经完成；不能将这些测试视为真实邮件投递证明。

## 1. 已有内容

全英文认证页面：`/login`、`/signup`、`/verify-email`、`/forgot-password`、`/reset-password`、`/auth/callback`、`/dashboard`。认证页面使用独立极简黑白设计、浅深主题、密码显示/隐藏、长度与确认校验、辅助强度提示、加载状态和英文错误提示。现有八模块业务页面保留原有语言和功能。

后端通过官方 `@supabase/supabase-js` 调用注册、密码登录、验证邮件重发、密码恢复、令牌验证、密码更新、会话刷新和退出。没有生产环境模拟账户、模拟邮件或假成功响应。

保留当前 Node HTTP + 原生页面架构，没有为认证重写整个项目为 Next.js。Supabase 管理认证账号与密码，本项目不存储密码。业务数据库仍为原有 SQLite，不代表已改造为云端多租户应用。

## 2. 创建认证项目

1. 在 Supabase 创建项目，记录 Project URL 和 **Publishable key**（旧项目可用 anon key）。不要使用 `service_role` 或 `sb_secret_` 密钥。
2. Authentication → Sign In / Providers：启用 Email，允许注册，打开 **Confirm Email**。
3. 将 Password minimum length 设为至少 8，与本项目环境变量一致。额外的字符要求、泄漏密码检测由 Supabase 决定；前端强度条只是输入辅助，不能代替提供商策略。
4. 配置自有 SMTP 服务与发件身份，完成邮箱/域名验证，并检查发送配额、速率限制和邮件垃圾箱。Supabase 默认发送服务有使用限制，不应当作正式生产邮件服务。
5. Authentication → URL Configuration：设置 Site URL 和允许的 Redirect URL。本机网页示例：

   - Site URL：`http://127.0.0.1:3100`
   - Redirect URL：`http://127.0.0.1:3100/auth/callback`

   桌面独立服务使用 `http://127.0.0.1:3102`；正式部署使用自己的 HTTPS 域名。不要使用任意域名通配符。确认入口、环境变量和提供商允许列表一致。

## 3. 必须修改的邮件模板

默认 Supabase 邮件链接可能将会话放入浏览器 URL fragment。本实现不接收前端 access_token，而使用 token_hash 服务端验证，因此需修改以下模板。

**Confirm signup** 的链接：

```html
<a href="{{ .RedirectTo }}?token_hash={{ .TokenHash }}&amp;type=email">Verify email address</a>
```

**Reset password** 的链接：

```html
<a href="{{ .RedirectTo }}?token_hash={{ .TokenHash }}&amp;type=recovery">Reset your password</a>
```

应用始终传入 `APP_ORIGIN/auth/callback` 作为 RedirectTo。核对邮件中的最终链接，不应出现空 RedirectTo 或重复问号。关闭邮件链接跟踪重写。

链接先打开一个确认页面，用户点击按钮后才 POST 到后端消费令牌，减少邮件安全扫描提前消耗链接的情况。令牌从地址栏移除；如果确认前刷新页面，需要重新打开原邮件链接。

## 4. 本地环境配置

根目录复制 `.env.example` 为 `.env`，填入下列值。不要提交真实密钥。

```dotenv
SUPABASE_URL=https://YOUR_PROJECT.supabase.co
SUPABASE_PUBLISHABLE_KEY=YOUR_PUBLISHABLE_KEY
OMNIFORM_AUTH_APP_URL=http://127.0.0.1:3100
OMNIFORM_AUTH_PASSWORD_MIN_LENGTH=8
OMNIFORM_AUTH_ALLOWED_EMAILS=YOUR_VERIFIED_EMAIL
OMNIFORM_AUTH_REQUIRED=false
```

先保持 `OMNIFORM_AUTH_REQUIRED=false` 联调认证页面，原免登录工作区继续可用。此模式不提供业务工作区登录保护。

验证注册、收件、确认、登录、找回密码、退出后，再设置：

```dotenv
OMNIFORM_AUTH_REQUIRED=true
```

必须同时配置 `OMNIFORM_AUTH_ALLOWED_EMAILS`。它是**现有共享业务工作区**的邮箱白名单，多个地址用逗号分隔。新注册用户默认只有自己的账户页，无权读取已有考试、审批或实验数据。不要把所有注册用户都视为工作区管理员。

可选设置：

```dotenv
OMNIFORM_AUTH_TERMS_URL=https://YOUR_DOMAIN/terms
OMNIFORM_AUTH_PRIVACY_URL=https://YOUR_DOMAIN/privacy
OMNIFORM_AUTH_DATA_PATH=C:/PRIVATE_DIRECTORY/auth
```

法律文档需由你提供真实内容；未提供时界面不会显示假的条款链接。Google OAuth、MFA 和 Passkey 未实现，不会出现无效的 Google 登录按钮。

重启服务使配置生效。网页登录入口：`http://127.0.0.1:3100/login`。

## 5. 桌面端注意事项

桌面服务端口是 3102，用户配置位置由 `%APPDATA%/OmniFormOS Desktop/workspace.json` 的 `envFile` 指定；未指定时会读取桌面数据目录的 `.env`。

网页与桌面应各自使用正确的 canonical origin 配置。不要将网页的 3100 地址直接当作桌面 3102 的地址，否则同源校验会拒绝提交。

验证邮件可能由系统默认浏览器打开。完成邮箱验证后，可以回到桌面应用输入账号密码登录；浏览器 cookie 不会自动同步到 Electron 的独立会话分区。密码找回也可在默认浏览器完成。

## 6. 安全与部署

- 正式对外使用 HTTPS，反向代理到现有仅监听 127.0.0.1 的 Node 服务，保留原 Host，设置 canonical HTTPS origin。未配置 HTTPS 时，仅允许本机 HTTP 开发地址。
- 本地 cookie 为 HttpOnly、SameSite=Lax、7 天有效；HTTPS 配置下附加 Secure。cookie 不携带 Supabase 令牌。
- Provider access/refresh token 仅在服务端 AES-256-GCM 加密会话库中保存。此数据库没有用户密码。加密密钥文件仅供服务端读取，部署时限制目录访问权限。
- 会话记录只保存随机 cookie ID 的哈希。服务重启后可继续读取，并重新向 Supabase 验证用户；临近过期时刷新令牌。同一个本地会话的并发刷新会合并。
- 邮件验证和密码恢复令牌由 Supabase 生成和校验；本项目不生成自制邮箱令牌或密码哈希。
- 登录、注册和邮件请求有持久化速率限制。同源 Origin + JSON 检查用于防止跨站提交。恢复会话只能更新密码，不能打开业务工作区。
- 重置后移除本账户的本地会话，并请求 Supabase 全局退出。提供商 JWT 本身在到期前通常不能即时撤销；不要把退出等同于吊销所有已签发 JWT。
- 忘记密码返回中性说明，不透露邮箱是否注册。异常信息不直接转发提供商内部错误，不记录密码、令牌或完整请求体。
- 现有公开考试/表单链接继续由对应模块的 token 与访问权限校验保护；登录白名单不是对所有公开业务入口的替代。
- Auth 会话与会话密钥不包含在八模块业务备份或桌面安装包中。

本次适用于单台工作区服务器。多实例部署前需要共享会话存储、分布式刷新锁与速率限制、可信代理客户端地址策略；尚未实现账号隔离的数据租户、组织角色体系或云同步。应在这些边界内上线，不宣称已经完成整个企业级身份平台。

## 7. 联调验收清单

1. 新邮箱注册，实际收件后确认，访问账户页。
2. 未验证邮箱登录，收到中性且明确的验证提示。
3. 重发邮件冷却、过期/重复使用链接处理。
4. 密码登录成功、错误密码失败，页面刷新和服务重启后会话保持。
5. 无痕窗口打开 `/dashboard` 进入登录；开启 REQUIRED 后根页面和业务管理 API 也需授权。
6. 未加入白名单的已验证账号只能查看自己的账户页。
7. 已知/未知邮箱忘记密码均返回中性确认；实际邮件链接可设置新密码，旧密码不能再登录。
8. 正常会话不能直接调用 reset API；恢复会话不能读取业务数据。
9. 退出后原 cookie 再请求账户与管理 API 被拒绝。
10. 测试 320px、768px、桌面，键盘 Tab、错误焦点、密码显示、主题和导出/登录页面兼容性。
